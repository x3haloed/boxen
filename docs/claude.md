# Claude Code runtime

Boxen runs the installed Claude Code CLI under the workload account. Install Claude Code and complete `claude auth login` as that account on the executing host. The official CLI owns sign-in and subscription access. Boxen discovers the executable on the daemon's PATH or in the workload account's `.local/bin`. An explicit `serve --claude /opt/example/bin/claude` or `BOXEN_CLAUDE` sets the executable. [CLI reference](https://code.claude.com/docs/en/cli-reference) · [Authentication and credential use](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use)

The runtime ID is `claude` in `start --backend claude`, `resident-create --backend claude`, and authenticated submissions. The target daemon advertises the runtime through `runtime_info`. The `claude_models` operation starts the local CLI in catalog mode without inference, session persistence, or workload MCP. It projects the model IDs and labels the CLI offers and caches the successful result for up to a minute for the same execution account. Desktop New Thread and Run settings → Choose a model, and the existing browser thread and resident pickers query the selected machine. The default uses Claude Code's `default` model selection. The runtime still determines whether the account can execute a particular model.

Claude Code owns the native session. Ordinary follow-ups and resident activations resume it using the retained native session ID. A known missing session or a recorded relocation uses bounded retained Boxen history to start a replacement session. The journal records the reason and previous native binding. Hidden runtime state and omitted payloads remain unavailable. Reconstruction supplies historical tool effects as evidence without redispatching them.

The native stream feeds Boxen's run journal, including assistant and thinking updates, tool activity, and tool results. Retained attachments are available as file references. A per-run HTTP MCP connection exposes the same daemon-owned operations as the other managed runtimes. A resident can explicitly send selected replies or finish without sending. Its output remains private narration.

Native prompt completion and run settlement are separate. A tool may return a background task handle while the task is still running. The original run owns the task's terminal notification and any new prompt Claude starts in response. The active run accepts cancellation. The adapter sends native interrupt and stop requests and treats an unconfirmed stop or lost stream as interrupted execution with potentially unknown effects. A new ordinary follow-up can start after the run settles. The runtime currently advertises cancellation, native resume, and late activity. Interactive steering and operator responses to native questions are outside this interface.

The controlled protocol suite runs with `python3 scripts/claude-smoke.py` and in the portable Linux rotation. The optional live check `python3 scripts/codex-runtime-live.py target/release/boxen --claude /opt/example/bin/claude --claude-background` uses the account's plan and exercises execution, resumption, selective correspondence, no-send completion, and a background wake.
